# Claude Desktop Mods

[English](claude-mods.en.md) · [文档首页](README.md)

此适配面向 **Claude Desktop → Code → 本地会话**。使用原生 AbovePrompt、Pane 和消息渲染，复用本机 Amoji 库。普通 Claude Chat/MCP Apps 是另一个宿主面；本指南不表示它已适配。

完整安装和使用步骤见[插件说明](../plugins/amoji-claude-mods/README.md)。当前源码有适配器，已发布的 v1.0.0 仍只包含 dsh；不要从旧标签推断包含 Claude 包。

## 三层边界

```text
Claude 原生 UI / Mods 事件 / 模型调用
          ↓ 纯 JSON 命令（stdin），真实会话和回合
src/claude-mods：宿主桥接、标记、缩略图、本地文件 IO
          ↓
src/application：交互用例、范围浏览、创建确认、建议输入/输出约束
          ↓ 公共客户端/端口
SharedClient → 共享服务 → LibraryStore / 不可变资产和消息
```

共享层不引用 Claude 的 `$`、控件、事件名、标记或模型 SDK；后续 Codex 可以复用用例，自己实现身份、呈现、提交与生成接口。dsh 继续使用其已验证的宿主协议，无须迁移数据。

Claude 的沙盒只能静态追踪同文件内的 `$` 调用，因此 `src/claude-mods/native/` 的可读模块被构建为单一 `hooks/register.js`。共享领域与 Node 代码没有被塞入这个受限环境。

## 双向消息

人工发送先通过共享服务按请求 ID 创建冻结消息，再调用 `$.prompt.submit`；只有文字标记和固定语义进入会话。AI 工具只接受查询或本回合选择凭据，真实 session/turn 从宿主事件取得；子代理不能借主回合发送。

渲染器仅将同会话、同方向的已存消息标记变成图像，普通文字仍保留。未知、伪造、跨会话和被改写的人工消息保持原文。历史引用冻结版本，不随画风、归档或新版本变化。

图片直接通过原生 Markdown 显示 AVIF/WebP 位图，不使用 SVG。列表最长边为 152 像素，对应 76 CSS 像素的双倍精度；消息与详情最长边为 192 像素，小图不放大。由于宿主每个面板共享 100k 文本预算，列表每张 AVIF 限制为 3,350 字节，超出时降低编码质量而不继续缩小尺寸。原始图片完整保留。表情网格连续滚动，不显示分页；Claude 适配器预读最多 64 项到会话内存，仅将可见窗口内至多 20 张图片交给宿主绘制，并保留列表的完整滚动高度。缓存内滚动不启动本地进程；重新搜索、切换列表或刷新会重新读取数据。图片不发送给模型，动画使用静态封面。

两套内置风格的列表和详情位图在打包时生成，第一次切换也无需现场编码。个人素材按原图摘要、显示规格和编码版本持久缓存，坏缓存自动从原图恢复。切换画风合并为一次本地请求，读取完成前保留当前列表，完成后整体替换；重复选择同一画风不发请求。

提交拒绝、结果未知、服务冲突都显示错误，不自动重试可能已经生效的操作。

## 发送反馈与消息呈现

图片点击后先显示「正在发送」，提交被宿主接受后显示「已发送 · 等待 Claude 回复」。等待提示只随对应主回合结束而解除，不会被其他回合或子代理提前清除；发送失败保留可理解的错误，不自动重试。模型响应时间与本地发送时间分开，插件不能保证模型在固定时间内回答。

表情消息遵循 Claude 原生布局：用户在右侧，AI 在左侧，不增加「你」或「Claude」等角色标签；表情名称只显示一次。侧栏使用紧凑网格，去掉重复标题、关闭按钮与每张图片下的重复发送行。搜索分别呈现加载、失败和空结果，空结果提供「显示全部」和「创建表情」。已有创建、导入导出和偏好入口保持可用。子代理视图提示返回主对话，避免把表情发往错误对象。

人工发送返回已冻结消息的显示投影，渲染时复用；同一历史消息的并发读取合并，最多缓存 128 条。缓存仅存在于当前会话的宿主适配器中，不改变共享语义或传给模型的纯文本格式。

## 与 dsh 对齐的使用流程

- **选择器**：打开「表情」，直接切换经典/办公画风，按进度、澄清、方向、反馈等场景筛选；点击图片或名称立即发送。连续滚动，无分页。
- **管理表情**：与快速发送分开，包含表情库、创作与草稿、AI 偏好、导入与导出。宽屏为左侧导航，窄侧栏使用页面切换菜单；返回选择器保留搜索和场景。
- **创作与草稿**：明确新建或恢复已有草稿后，填写一段意图，选择模型并生成建议。采用后先显示语义摘要，点「编辑语义与来源」才展开字段。图片与语义仍需保存、预览和核对才能入库。切换草稿前可保存修改、明确放弃或继续编辑。
- **宿主差异**：字体、控件配色与面板外壳跟随 Claude。文件使用本地路径，动画显示封面；发送后保留侧栏，避免当前 Desktop 的程序关闭展开面板问题。没有把网页弹窗、文件选择器或自动折叠冒充为 Mods 已支持的功能。

## 验证和限制

- `npm test`：共享用例、持久化、隔离、媒体与桥接行为。
- `npm run test:claude`：官方 Mods strict validate 与控件/事件测试，测试不请求模型。
- `npm run test:claude-artifact`：安装实际包内锁定依赖，以隔离数据目录启动实际服务并读取基础库和缩略图。
- 真机验收需单独观察 Claude Desktop 中的选图、发送、模型工具回赠、两侧图片、创建预览与确认、偏好和导入导出。测试工具不等于屏幕绘制。

Mods 没有公开文件选择器，文件输入采用本地路径。UI 语言跟随 `settings.language`，未设置时中文；Desktop 应用自身的语言设置不在此 API 中。模型选项使用当前模型、Claude 别名及自定义 ID，由宿主校验可用性，不声称获得完整模型目录。

构建目录 `.cache/claude-mods` 是一个本地 marketplace。分发包为可移植 ZIP，依赖按锁文件安装，未捆绑 Sharp/libvips。CI 构建、检查后追加到 GitHub Release 的统一校验和与 provenance，实际发布只发生于显式推送版本标签。


## 真机验证范围

2026-10-11，在 Claude Desktop 2.31226.1、内置 Claude Code 2.1.295 的隔离本地项目和表情库中，使用 Haiku 5.5、低投入完成以下真实界面验收：

- 输入区入口、表情缩略图、原生发送按钮；人工消息显示图片，模型按固定语义回应。
- 图片点击层的中心、边角、重绘后命中，以及右键和拖出取消已真机验证。交互修订后单击「还在吗」，约 0.38 秒写入一条纯文本用户消息，随即显示等待回复；模型约 4 秒后答复，等待提示正常消失，面板保持打开。这是一次实测，不是延迟保证。
- 重设计后的复测：在 Haiku 5.5 / 低投入会话物理点击「谢谢」图片，约 1.1 秒后的界面观察已显示提交被接受、等待回复；随后一条用户图片消息与 Claude 的文字答复分别显示在右侧和左侧，等待提示清除。1.1 秒包含电脑控制工具与截图开销，不是底层发送耗时或性能保证。本次布局验收只进行了这一轮模型请求。
- 纯位图复验：经典与办公风格切换均显示正常，连续滚动可看到第 25 张表情；点击「谢谢」图片直接发送，右侧显示清晰的用户图片，左侧显示 Haiku 5.5 的文字回复，等待提示正常解除。此轮只调用一次模型，会话记录中的表情输入仅含文字、没有图片块。安装文件与本地构建产物已逐项核对。
- 用户表情右对齐，Claude 文字回答保持左侧。新版网格支持一至四列；本轮真机观察了三列侧栏、四列展开及快速往返滚动，未出现原先等待缩略图时的空白。长名称在网格中省略，图片替代文字和详情保留全名。搜索空结果、显示全部、点图查看详情、选择/取消选择、偏好分组和已有草稿恢复均经真机检查。键盘切换页签属于此前的真机验证。
- AI 实际调用 `search` → `emit`，回复“收到，我来处理。”并显示表情；重新加载插件后，两侧历史图片仍正确重绘。
- 创建页默认读取当前对话模型；从单段意图生成文字建议，明确采用后编辑，保存、恢复草稿，预览核对并确认入库。
- 并发写入冲突时核对最新内容、另存本地输入和原图片，验证原草稿保持另一写入者的版本。
- 搜索新表情、导出 `.amoji`、文件错误提示和修正重试、重复导入不新增重复版本、归档与恢复。
- 切换办公画风，既有经典风格消息保持原图；界面随 Code 的中文/英文配置切换。

自己的测试会话记录确认人工表情仅有文本输入块，没有图片块。真实 AI 回赠也使用文本工具结果和消息标记。模型仍接收 Claude Code 自身的系统上下文；这不是对整场会话输入 token 或费用的固定承诺。AI 文字建议只提交意图和固定系统提示。

Desktop 的表情选择器支持点击图片直接发送。图片由主界面的 `Markdown` 直接绘制，同一个定位容器中的透明 `Client` 处理完整左键按下与松开，经 `surface.post` → `ui.message` 调用原有发送用例。根容器与点击层均使用明确的 9×4 单元格尺寸，避免当前 Desktop 将百分比高度缩成一行。右键、修饰键、拖拽和移出取消；重绘保留实例，滚动窗口更新目标身份，成功提交后拒绝迟到的重复事件。宿主层仅接受当前会话、面板、模块和可见表情的事件，不相信客户端提供的表情语义。共享应用层不依赖这些 UI 接口。

桌面网格点击图片或名称直接发送，名称按钮保留原生键盘入口；在「管理」中点击名称查看固定含义。终端和图片点击层故障时，仍可通过名称按钮发送。当前 SDK 没有公开的指针光标设置。Markdown 图片链接在重绘后的回调存在不稳定性，因此不用于发送。参见 [Mods 接口参考](https://code.claude.com/docs/en/plugins/mods/reference) 和 [重绘事件问题](https://github.com/anthropics/claude-code/issues/99211)。

发送后面板保持打开，避免当前 Desktop 在关闭展开面板时留下空白布局。需要收起时使用宿主右上角的关闭或折叠控件。公开 Mods API 没有展开/折叠控制。

原生文件选择器和动画播放不在当前支持范围内。模拟控件测试与真实绘制、点击、模型回复必须分别验收。

当前 Desktop 的原生按钮句柄可能在焦点重绘时过期，宿主日志会记录 `ui_press not handled`。新版入口、导航和操作按钮保留原生外观与键盘能力，鼠标使用稳定 key 的 Client 完整点击事件，交由当前页面的操作映射执行；过期页面和伪造操作不执行。Client 运行失败时退回原生按钮，可使用回车。输入框和下拉菜单仍由宿主处理。参见 [Claude Code #99211](https://github.com/anthropics/claude-code/issues/99211)。

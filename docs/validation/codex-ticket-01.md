## 请求观测的范围

`scripts/probes/wire-relay.mjs` 只绑定回环地址，将请求原样转发至固定 OpenAI/ChatGPT 后端。认证头只在内存中透传，不写文件；不记录原始 prompt、图片字节或完整请求。统计对象来自真实 `body.input`，包括内容块类型和图像 Data URL 数量。

这证明列出的测试请求没有图像输入，**不是对所有宿主、所有会话状态或所有模型的泛化承诺**。模型理解依赖返回的文字语义，正常工具路径没有图像识别调用。浏览器截图和素材生成在开发会话中进行，未作为被测模型的输入。

转发器只实现 `/responses`，测试过程出现 `/models` 404 警告；测试使用宿主已有默认模型。另观察到已有插件缓存锁与 Notion 认证警告，没有更改这些无关组件。工具成功以实际工具返回判定，不以 CLI 退出码或模型口头声称判定。

## 已运行的失败与限制

- 第一次只读探针没有 MCP 只读注解，调用被要求审批而失败。补上符合实际行为的 `readOnlyHint` 后两个版本均成功。没有把首次失败改记为跳过。
- 安装产物首次验证使用了错误的 CLI 配置键引号，插件名被解析为包含字面引号的名称，工具未加载。改正后又发现 MCP 参数中的 `${CLAUDE_PLUGIN_ROOT}` / `${PLUGIN_ROOT}` 未展开，初始化失败。最终用每台机器构建时物化的启动配置修复，安装版复验通过；前述失败不改记跳过。
- 内置引擎的安装版测试在 `--ignore-user-config` 下没有发现工具，虽然其进程退出码为 0。保留插件安装发现配置后复验成功。安装版探针可能同时启动用户已有的其他 MCP；不把其他服务的认证警告计为 Amoji 失败，也不将模型的口头成功作为工具证据。
- 新 CLI 的内联 Hooks 产生有效事件；旧内置引擎本次没有对应 Hook 记录。因此实际适配直接依赖已实测的 MCP 元数据。
- 共享 CLI daemon 的控制 socket 不存在；`queue` 命令的存在不能证明可向当前 Desktop 会话输入。
- CUA 明确拒绝访问 `com.openai.codex`。导航到测试会话成功，仅说明页面导航，不算主界面目视验收。
- 两会话隔离目前有真实 HTTP/MCP 合同测试，尚未完成两个同时打开的真实 Desktop 会话切换。
- 2026-09-05 后续浏览器补验时，CUA 报告 Mac 已锁定且自动解锁失败。安装版新 CLI 已进入 `amoji_pick` 等待，但没有完成用户点选；这次不算双向通过。新增加的完整历史详情和重启后视觉恢复尚未在浏览器目视复验。

启动配置的依据与局限：参考 [Codex 插件文档](https://developers.openai.com/plugins/build/plugins) 与本机两个 CLI 的 `mcp get` / 真实调用。官方支持插件内 MCP 声明，但本次实际加载路径没有展开占位符。`.mcp.json` 因此是本地构建产物，不进 Git；个人市场安装后仍需保留 `~/plugins/amoji` 的运行时。此结论仅针对列出的已测版本和加载方式。

## 复验

1. `npm ci && npm run build`；运行 `node scripts/probes/live-tools.mjs`，检查实际 MCP 返回。
2. 运行 `AMOJI_PROBE_PICK=1 node scripts/probes/live-tools.mjs`，在打开的面板选择并发送一个样本，观察 AI 回应图片；换样本重复。
3. 用输出的测试会话 ID 运行 `AMOJI_RESUME_THREAD=<id> node scripts/probes/live-tools.mjs`，检查回放的请求统计。重开面板时，再加入 `AMOJI_PROBE_PICK=1` 和原运行输出的 `AMOJI_DATA_DIR`；先观察旧图片与完整定义，再发下一张图。
4. 在已经加载 Amoji 插件的新 Desktop 会话中调用技能，完成同样视觉检查；同时打开第二个会话，核对面板显示的完整会话标识，验证不会串话。
5. 每次仅检查本次生成的临时日志；不要提交未经筛选的登录配置、请求头、会话原始记录或面板能力 URL。

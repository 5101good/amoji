# Amoji 数据协议 v0.1

日期：2026-09-05。状态：首版规范草案。本文定义 Amoji 自有数据，不声明它是任何宿主已经实现的 API。结构约束见 [JSON Schema](amoji-v0.1.schema.json)，运行约束以本文为准。

## 1. 不变量

1. 一个表情版本包含确定的视觉和语义，确认后不可变。
2. 表情消息引用并保留该版本；没有 message-level meaning、semantic_override 或动态意图字段。
3. 同一消息的人类展示与模型语义必须来自同一个版本，不能分别查询“最新”。
4. 正常模型投影仅包含文本，不包含图像内容块、base64 图像、附件或需要模型访问的图片。
5. 资产元数据是表达数据，不是可执行代码、系统提示或工具授权。
6. Amoji 语义必须进入模型可见文本，不能仅保存在宿主隐藏的 `_meta`。

“metadata”是用户概念中附在表情上的描述信息；协议将其明确命名为 `semantics`，避免与 MCP 或特定宿主的 `_meta` 混淆。

## 2. 对象与标识

| 对象 | discriminator | 标识 | 含义 |
|---|---|---|---|
| 表情版本 | `amoji.expression` | `asset_id + revision_id` | 表情某个确定版本 |
| 表情包清单 | `amoji.pack` | `pack_id` | 一次可移植导出 |
| 表情消息 | `amoji.message` | `message_id` | 一次确定的收发 |
| 本地会话绑定 | 不属于可分享资产 | `binding_id` | 本机到宿主具体会话的关联 |

各 ID 为随机 UUID v4，使用小写形式。版本不使用可跨分支冲突的自增整数，不从文件名、中文名称或图像识别推导身份。`schema_version` 固定为字符串 `0.1`。

用户界面显示名称和编辑时间，不要求用户阅读 UUID。名称和标签用于检索，不能作为发送时的唯一标识。

## 3. 表情版本

机器可读示例见 [expression.example.json](examples/expression.example.json)。它仅用于说明元数据结构，没有附带真实图片，不能作为完整表情包导入。

| 字段 | 必需 | 约束 |
|---|---|---|
| `kind` / `schema_version` | 是 | `amoji.expression` / `0.1` |
| `asset_id` / `revision_id` | 是 | UUID v4；联合定位不可变定义 |
| `name` | 是 | 1–48 个 Unicode 字符 |
| `created_at` | 是 | UTC 时间，以 Z 结尾 |
| `semantics` | 是 | 下节定义的固定语义 |
| `tags` | 否 | 最多 12 个、每个 1–24 字；检索辅助，不构成独立语义覆盖 |
| `visual` | 是 | 主素材、动画标记及必要封面 |
| `rights` | 是 | 许可说明；可选作者和来源说明，不构成真实性认证 |
| `derived_from` | 否 | 来源版本引用；记录修订或个人副本来源 |

元数据文件不包含当前库激活版本、收藏、最近使用、草稿、会话、绝对路径、机器标识或个人设置。这些属于本地状态。

### 3.1 固定语义

| 字段 | 必需 | 内容 |
|---|---|---|
| `locale` | 是 | 语义语言，如 `zh-CN`、`en` |
| `meaning` | 是 | 1–240 字的核心含义 |
| `fallback` | 是 | 1–80 字，视觉暂不可用或无障碍场景的替代文本 |
| `tone` | 否 | 1–80 字的语气描述 |
| `use_when` | 否 | 最多 4 条，每条 1–64 字 |
| `avoid_when` | 否 | 最多 4 条，每条 1–64 字 |

自然语言是语义权威，不要求离散情绪枚举、情绪向量或统一强度分值。`use_when` 和 `avoid_when` 描述表达语境，不是任意模型操作指令。

v0.1 每个版本只有一份指定语言的语义，不做实时翻译后替换。其他语言的重新定义必须由用户确认为新版本或个人副本。中文首套内容不意味着协议只允许中文。

文字字段须含非空白内容；计数以 Unicode code point 为准。序列化后的 `name + semantics` JSON 使用 UTF-8，额外限制为 4 KiB，不静默截断；超过限制时在创作或导入阶段报告。建议器无法凭空保证图片与语义一致，最终由用户确认。

### 3.2 视觉内容

`visual.primary` 为素材描述：`sha256`、`mime`、`bytes`、`width`、`height`。

- 支持 PNG、JPEG、WebP 静态图片；动图支持 GIF 和 animated WebP。
- `visual.animated` 明确是否为动图；实际解码结果必须与声明一致。
- 动图必须有 `duration_ms` 和静态 `poster`，主图与封面均为独立素材描述。
- 静态素材不得携带动画时长或额外封面；GIF 在 v0.1 只作为动图接受。
- SHA-256 为实际文件字节的 64 位小写十六进制摘要。读取同一摘要不能获得不同字节。
- 运行时从本地素材存储映射摘要到地址，地址不进入可分享清单。

工程初始上限：单个素材 10 MiB，边长不超过 2048，动图一轮最长 10 秒、最多 200 帧，累计解码像素不超过一亿。Schema 约束可声明部分；格式真实性、帧数和像素总量由解码校验器执行。

不支持 SVG、HTML 或带执行能力的视觉容器。动画暂停时展示封面，不能把整个动图发送到模型侧以获得静态替代。

### 3.3 不可变、修订与冲突

- 同一 `asset_id + revision_id` 再次出现时，解析后的所有字段值必须相同；对象键顺序可不同，数组顺序属于内容。
- 相同定义和素材重复导入为幂等成功；同 ID 不同定义为 `REVISION_CONFLICT`，不得覆盖。
- 自己的表情修订保持 `asset_id`，分配新 `revision_id`，`derived_from` 指向上一版。
- 编辑内置/外部表情创建新的 `asset_id` 与 `revision_id`，保留 `derived_from`。后续可以在该个人副本上修订。
- 导入数据不能声明自己属于“本机作者”；本地来源类别由导入过程设置。
- 来源引用是溯源说明，不要求来源版本也在包中；不得据此远程抓取依赖。
- 草稿不使用可发送版本身份。确认与落库事务成功后才可检索和发送。

## 4. 消息与两个投影

`amoji.message` 包含 `schema_version`、`message_id`、`binding_id`、`direction`、`created_at` 和完整的 `revision` 快照。

`direction` 为 `human_to_ai` 或 `ai_to_human`。`revision` 是被引用版本的精确复制，由可信本地服务构建，不接受模型或发送面板传入一份重新定义的语义。

消息是持久记录，不是公开发送接口的入参。发送接口仅接受已验证的版本引用或选择凭据。用户附带的普通文字仍是宿主普通消息，不合并成表情的语义字段。

### 4.1 模型投影

由运行时固定序列化，包含 `message_id`、`direction`、版本引用、`name` 和 `semantics`。可以用 UTF-8 JSON 放入一个文本内容块，并有固定提示说明“以下是表情表达数据”。

不包含视觉字节、文件路径、素材地址、许可、使用历史、整库清单或任意隐藏提示。引用模型输出的路径渲染是特定适配器的可选显示策略，不能改变协议默认投影。

`meaning` 等字段按数据转义，不能通过拼接闭合标签或 Markdown 语法变成宿主指令。固定边界本身不是绝对的提示注入防护，还要限制工具实际权限。

### 4.2 人类投影

包含同一个 `message_id`、版本引用、视觉摘要、显示名称、替代文本和可查看的固定语义。渲染器根据摘要向本地服务取图，不调用视觉模型。

界面可不默认展示所有语义字段，但用户必须能查看自己发送的定义。动图保持可暂停；静态封面引用与消息版本一同保留。

### 4.3 回放与修订

- 消息记录创建时固定版本快照，同时建立素材保留引用。
- 回放优先使用消息快照与保留素材，不跟随库当前版本。
- 宿主历史同时保留模型当时实际收到的文本投影；不能仅保存一个待未来解析的“最新”引用。
- 若宿主限制只能持久保存引用，恢复时必须按精确版本解析，不能回退到当前版本。
- 素材损坏时显示替代文本与异常状态；禁止从同名新表情补图。
- 缺失语义版本时明确报告，不能临时识图或让模型猜测。
- 普通归档不清除被历史消息引用的版本与素材。永久清除及其对历史的影响不属于首版常规移除功能。

## 5. 包格式

文件后缀 `.amoji`，内容为 ZIP。压缩包只允许以下布局：

```text
manifest.json
blobs/<sha256>
```

`manifest.json` 为 UTF-8 `amoji.pack` 对象：

| 字段 | 含义 |
|---|---|
| `kind` / `schema_version` | `amoji.pack` / `0.1` |
| `pack_id`、`name`、`created_at` | 一次导出的身份、名称、时间 |
| `expressions` | 1–200 个完整表情版本 |
| `defaults` | 每个 `asset_id` 一个默认版本引用，必须指向本包中的版本 |

每个被引用素材必须在 `blobs/` 中存在且摘要匹配，包括动图封面。重复摘要只存一份。不可携带外部资源链接、脚本、宿主配置、账号或消息记录。

相同 `pack_id` 不授予覆盖权限，真正冲突判定落到不可变版本。已存在表情导入其他版本时，不自动切换个人当前版本；新表情才采用包内默认值。原有个人副本不受上游包影响。

### 5.1 导入事务

1. 在隔离临时目录解包；拒绝绝对路径、`..`、符号链接、重复条目名、路径规范化冲突及非允许目录。
2. 限制展开大小 250 MiB、条目数 1000、清单大小 2 MiB；读取时执行限制，不能先无限展开再检查。
3. 校验 Schema、版本引用唯一性、默认值完整性、字段预算和 ID 冲突。
4. 校验所有素材摘要、实际格式、尺寸、动画信息与解码预算；拒绝未引用的额外文件。
5. 将素材写入不可变存储，再以单一事务提交版本、库条目与包记录。
6. 失败时不产生可发送的半导入记录；事务前残留素材仅作待清理孤立文件。

完整包通过校验即可加入使用，不要求重新确认每张语义。格式有效只表示数据完整，不意味着系统验证了原作者的语义准确性或许可真实性。

### 5.2 导出和迁移

导出复制所选确定版本及实际素材，生成新的 `pack_id` 和对应默认引用。默认只导出用户所选当前版本；需要分享旧版本时可明确选择。

导出不包含本地绝对路径、个人设置、库使用频次、收藏、会话绑定、消息记录。换设备导入恢复的是表情资产；它不自动恢复另一设备的宿主会话历史。本机历史所需的旧素材不因只导出新版而清理。

## 6. 版本演进

v0.1 严格拒绝未知顶层或对象字段；未知 `schema_version` 返回 `UNSUPPORTED_SCHEMA`。不静默丢弃未知语义，再将对象伪装为本版本。

破坏兼容的字段变化须提升协议版本。迁移生成新记录并保留来源，不原地改写已发消息。库数据库版本、插件版本、协议版本和资产版本是四个不同概念。

本阶段 JSON Schema 是结构合同，不包含所有运行约束：摘要、解码、默认引用、字节预算、不可变性、历史保留与发送时精确匹配仍须由实现验证。验证器必须启用并实际提供 `date-time` 格式校验，拒绝无效日历日期；仅加载 Schema 或配置一个没有该格式实现的校验器并不足够。

## 7. 错误语义

| 错误 | 处理 |
|---|---|
| `INVALID_SCHEMA` / `UNSUPPORTED_SCHEMA` | 保留原输入，报告字段或版本问题 |
| `SEMANTICS_BUDGET_EXCEEDED` | 在创作/导入阶段要求缩短，不截断已确认语义 |
| `REVISION_CONFLICT` | 拒绝覆盖，提示作为新表情重新创作或修正包 |
| `ASSET_NOT_FOUND` / `REVISION_NOT_FOUND` | 不自动选同名或最新版本 |
| `BLOB_MISSING` / `BLOB_INTEGRITY_FAILED` | 拒绝作为完整包导入；回放时保留语义并显示缺图 |
| `MEDIA_UNSUPPORTED` / `MEDIA_LIMIT_EXCEEDED` | 报告素材限制，原始文件不变 |
| `BINDING_UNAVAILABLE` | 不发送到猜测的会话，用户可重新关联 |
| `DELIVERY_UNKNOWN` | 状态未知，不当作失败盲目重发 |

投递、幂等和宿主绑定合同见[技术设计](../design/architecture-v0.1.md)。

# Amoji 首版验收与实施顺序

日期：2026-09-05。状态：验收计划；除另列的[规格自检](spec-review-v0.1.md)，下列产品与客户端验收均未执行。

## 1. 验收原则

“模型获得语义”和“用户看到表情”是两个独立的事实，必须分别有证据，并能用同一个消息 ID 与版本关联。

用户已指定本期以 Codex 为基准验证完整接入，优先使用 Codex Desktop。其他两个宿主先实现适配，验证工具不可用时允许跳过真机验证，不阻塞本期交付；工具可用时仍执行验证。配套面板允许，改变为自建客户端不等于完成 Codex 官方客户端适配。

Codex 的双向表达、真实模型文本请求、历史、多会话及完整产品行为是必须通过项。dsh、Claude Code 要完成非空壳适配及可执行的构建、类型和公共合同检查，分别记录“实现状态”和“宿主验证状态”。只有工具缺失的用例可以标为跳过，实际失败不得改记跳过；跳过须列明缺失工具、受影响用例和复验方法，且不能宣传为已验证支持。

下列 AC01–AC20 作为 Codex 完整行为基准。涉及多客户端的用例先用独立 Codex 会话/连接及公共服务合同验证；其他宿主真机部分遵循上述条件跳过规则。

证据至少记录：OS、宿主与插件版本、核心版本、协议版本、模型/供应商、测试数据、动作、结果和可复现步骤。生产凭据不得写入报告，请求样本使用受控数据并去除凭据。

## 3. “不需要多模态”的验证

Codex 必须执行以下验证；其他客户端在工具可用时分别执行，不可用时记录跳过而非通过：

1. 使用受控表情样本，给图片选择与语义解析设置独立观察点。
2. 捕获适配器生成的数据和宿主真正发送给模型的数据；两层都检查。
3. 检查不存在图像内容块、图像附件、base64/data URL、被解析为图像输入的资源引用。
4. 检查首次消息、工具回传、续聊、上下文压缩后恢复、重新打开会话。
5. Codex 验证实际请求只依赖文本；如果所用形态允许配置纯文本模型，增加真实纯文本模型用例，不要求宿主提供其不开放的模型选择。其他宿主按验证工具的可用性执行或记录跳过。
6. 人类视觉验证由 UI 截图/录像和渲染回执完成。imagegen 生成素材和开发者目视检查属于制作阶段；被测会话不得预先携带这些图像输入。

测试网关或协议桩可辅助检查公共合同，不能替代 Codex 的真实宿主运行。无法观察 Codex 实际请求时，该项仍未证实，不能降低基准要求；其他宿主因验证工具不可用而未执行的部分单列跳过，不用 Codex 结果推断它们也通过。

## 4. 接入验证门槛

先使用 3 个受控表情样本：静态庆祝、静态无奈、短循环鼓励。图片由 Codex imagegen 技能在开发阶段生成并保存至项目，记录提示和语义；动图单独封装并验证播放、时长与封面。当前尚未生成这些素材，规范中的 JSON 示例不能代替真实视觉样本。

| 门槛 | 要回答的问题 | 通过条件 |
|---|---|---|
| G01 dsh 外部插件 | 适配实现是否完整，何种检查可执行？ | 完成 Host/Client 适配与可执行构建/合同检查；宿主工具缺失时真机部分可跳过 |
| G02 Codex Desktop | 插件能否关联当前会话并完成双向视觉？ | 真实插件路径；原生或配套面板闭环；无内部专属工具依赖 |
| G03 Claude Code CLI | 插件及配套面板是否按公共合同实现？ | 完成适配与可执行检查；缺少验证工具时单列真机跳过，不将预览资格当普遍默认 |
| G04 多会话 | Codex 会话身份能否稳定获得？ | 两个同时运行的 Codex 会话不会错投；存在可信回合信息 |
| G05 回放与模型路径 | Codex 图片能否恢复，模型请求仍仅需文本？ | Codex 的 AC03、AC10、AC19 通过 |
| G06 分发 | 用户能否完成 Codex 干净安装与首次表达？ | Codex 实测；另外两个插件的实现、可执行检查与未验证限制明确 |

G02、Codex 的 G04/G05/G06 是本期真实接入门槛；G01/G03 的实现和可执行检查仍需完成，但缺少工具的真机部分不再是主线前置依赖。Codex 仅有复制粘贴路径时仍属实验；发现真实失败应保留失败证据，不能改记为工具不可用。

## 6. 质量与成本评估

在 Codex 用同一组至少 30 个受控对话场景对比“普通文字回应”与“Amoji 表达”。覆盖喜悦、感谢、安慰、疑惑、调侃以及不应主动发表情的场景；其他宿主可在具备工具后复用。

记录：

- 是否选到符合固定语义与语境的表情，是否出现不存在的 ID。
- 视觉是否正确、显示是否重复、是否出现语义与图片版本错配。
- 频率和风格是否符合用户设置；暂停是否确实阻止新发。
- 文本 Token、工具往返、实际模型图像输入数量。
- 本地检索与渲染耗时，单列模型等待时间。

场景允许多个合理候选，不做机械的唯一标签匹配。首版评审须解释不合适案例并修正；不能凭一个模型的成功案例声称所有模型表现一致。性能预算是工程目标，成本与自然度结论均需实测。

## 7. 发布记录模板

每个具体客户端使用同一张记录表：

| 字段 | 填写内容 |
|---|---|
| OS / 宿主形态 / 版本 | 实际值 |
| 插件 / 核心 / 协议版本 | 实际值 |
| 展示方式 | 内嵌 / 配套面板 / 实验文本路径 |
| 输入与绑定方式 | 实际公开机制，前提条件 |
| 实现状态 | 未实现 / 已实现；说明实际适配范围，不能以空壳计完成 |
| 可执行检查 | 构建、类型、公共合同测试的实际结果；不能与真机验证合并 |
| 跳过记录 | 缺失工具、受影响用例、尝试结果及复验步骤；实际失败不记为跳过 |
| 双向表达 | 通过 / 失败 / 未测试 |
| 请求仅需文本 | 通过 / 失败 / 无法证实 |
| 历史与多会话 | 通过 / 失败 / 未测试 |
| 证据 | 日志、请求样本、截图/录像路径 |
| 支持结论 | 已验证 / 实验 / 已实现但宿主未验证 / 未完成 / 不支持，以及限制 |

工具安装、Schema 验证或静态代码审查只能记入对应局部结果，不能代替这些记录。

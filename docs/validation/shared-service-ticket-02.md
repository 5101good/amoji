# 票据 02：共享服务实现与本地验证

日期：2026-09-15；环境：macOS arm64、Node.js 24.19.0。基线 `4a57952`，前置票据 01 的肯定 Desktop 证据为 `57e831a`。本记录只声明本地实现与可执行检查；新版安装版 Desktop 仍待主控验收，不关闭票据。

## 实际实现

- `LibraryStore` 集中保存不可变版本、当前库引用、内容寻址素材、消息快照、选择凭据和发送去重；服务独占 SQLite 写入锁。
- 独立服务通过私有发现文件、loopback 鉴权健康/API 握手和真实连接租约管理多个客户端；一个适配器退出只清理自己的关联。
- 公共 `SharedClient` 接受可信适配层的 host、instance、session、turn，服务发送只接收绑定句柄及精确引用/选择凭据。Codex MCP 与面板均通过它访问同一库。
- 旧小样数据库和素材只读复制到新库，原历史图片路径保留；未来数据库版本拒绝启动且不降级。
- 插件产物包含共享服务、公共客户端、Schema、面板、种子素材和依赖；修正原打包脚本把 npm 相对符号链接改写成开发工作树绝对目标的问题。

## 覆盖边界

- 两个真实独立客户端并发冷启动，只看到一个服务 ID 与数据根；不同会话消息隔离，一端退出后另一端继续读写。
- 服务重启后完整精确版本、动图/封面、消息 ID、展示回执和已消费选择凭据去重保留。
- API 不兼容、错误发现身份、停止身份错误、仍有活跃连接时停止均被拒绝；高版本数据库原文件字节不变。
- 两个真实 stdio MCP 进程共享选项与历史，模型工具返回仅一个文本内容块；面板按同消息 ID 回执，跨会话回执拒绝。
- 一个面板关联失效收口自己的 pending pick，另一连接仍完成实际 HTTP 点选并保存固定消息；服务终止时所有所属连接退出。
- 旧数据库、清单和旧图片文件内容不变，原会话历史及人工去重恢复；初始化后不重新合并旧原型状态。
- 临时插件产物在独立 cwd、没有 `AMOJI_SAMPLE_ROOT` 或开发 `NODE_PATH` 的环境启动，实际读取面板 HTML、动图和封面，依赖链接没有逃逸到构建工作树。

全部测试使用自己创建的临时数据根，没有调用真实模型、修改用户 Codex 配置、替换已安装插件或停止其他用户进程。素材继续使用票据 01 的三样本；没有预建 03–19 模块或管理功能。

## Standards fix round 1

审查后修复四项生命周期问题，并纳入主控在已安装 `64246ca` 产物中复现的双客户端冷启动超时：

- 停止接缝等原服务进程实际退出，确保内核写入锁释放；不再把发现文件消失当作完成。测试仅在自有子进程中延长真实 SQLite 关闭窗口，先复现错误返回，再验证立即重连成功。
- 首次候选以 75 退出时，在原 8 秒总预算内短暂随机退避并重新竞选。公开进程测试先观察真实 75 退出，再释放临时占用的真实锁；旧实现仍超时，修补后正常启动。
- 启动、检索及每分钟清理过期未消费凭据；已消费凭据随消息保留。独立服务测试推进受控时钟，核验删除效果和重启后的原 message_id 幂等。
- 增加 `unbind`，Codex 适配器在每次操作的 finally 释放临时绑定；删除每回合客户端缓存。测试用实际服务验证已结束操作的句柄不可再用，同时原在途句柄与重试仍有效。
- 测试清理仅忽略确认的 ENOENT，其余停止异常使测试失败；等待全部自有进程退出后才删除临时数据根。

客户端必需 `unbind`，服务 API 因此升为 **2**，数据库保持 **1**。新版客户端不会误连仍运行的旧 API 1 服务；管理员停止接缝继续兼容已知 API 1/2。安装产物的 serviceApi 从实际代码常量生成。

## 当前需要收敛的接入边界

1. 原 Spec 只设计三个日常工具。实现提供额外实验 `amoji_pick`：用户要求选表情 → 同一 MCP 调用等待本地面板 → 点选返回固定语义。它可绕开未经确认的 Desktop 直接消息插入 API。已向用户提问；作为可回退小样实现，**尚未将这一变化写入正式 Spec**。
2. CLI 0.151.0 和 Desktop 内置引擎 0.140.0-alpha.2 都在真实 MCP 请求中提供会话/回合元数据。后者以命令行方式运行成功，不等于 Desktop UI 全流程成功。
3. 电脑操作工具访问 `/Applications/Codex.app` 被拒绝：`Computer Use is not allowed to use the app 'com.openai.codex' for safety reasons.` 无法以该工具完成 Desktop 主界面目视检查。不使用其他截屏、私有输入 API 绕过限制。
4. 真实浏览器中已经观察到用户点选、固定语义预览、AI 回应图片和双向消息；恢复测试会话后的模型请求仍无图像输入。两个版本的安装插件均已实际检索和发送成功。**两个同时打开的真实宿主会话切换、全部三样本双方向矩阵、Desktop 主界面显示仍未完整验收。**
5. 补验时 CUA 另行报告 Mac 已锁定且自动解锁失败。已请求手动解锁；新代码的浏览器重启历史尚未目视复验。HTTP 合同测试已证明重启后可读取退出当前清单的历史动图、封面和固定定义，旧面板凭据不可复用。

因此，按已批准的依赖关系，不能将 01 标为完成，也不提前把 02–19 的空壳当作实现。用户放宽其他宿主验证的指示仍有效，尚未应用到未实现的适配器上。

## 小样的已知限制

- 已有专用于票据 01 的 SQLite 消息快照与版本冲突保护；暂无共享常驻服务或库编辑。
- 面板服务随 MCP 进程结束；已加载网页内容保留，但新发送不可用。
- 原生 Markdown 图片引用独立数据目录中的素材路径，Desktop 展示尚待目视确认；尚未实测真实插件卸载后的历史查看流程。
- 搜索为三样本文字子串匹配；尚未实现完整库的 8 KiB 总预算、克制冷却、风格/暂停设置和全套投递状态机。
- 样本语义仅用于开发验证，用户目视确认及正式分发许可未完成。尚不是 20–30 个正式基础表情。
- Issue Tracker 仍未配置；未创建远程票据。配置入口是 `/setup-matt-pocock-skills`，它不阻塞本地实现和审查。

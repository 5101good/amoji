# Amoji v0.1 规格自检记录

日期：2026-09-05。检查对象：PRD、领域词汇、数据协议、JSON Schema、三端技术设计与验收计划。

## 结论

后续范围修订：用户指定本期以 Codex 验证完整接入；dsh、Claude Code 先完成实现，在验证工具不可用时可跳过真机测试并记录。开发素材使用 Codex imagegen 技能生成。以下原有 Schema 自检结果保持有效，但不构成任何客户端已实现或已验证的证据。

规格文档已完成首轮一致性检查。Schema 验证通过 37 个结构断言，其中 8 个合法对象、29 个非法对象；示例可按协议字段解释，文档本地链接与代码围栏已检查。

这不是工程代码评审、模型效果评测或三端运行验收。本项目当前仍处于规格阶段。

## 1. 产品约束复核

| 约束 | 检查结果 |
|---|---|
| 独立表情体系 | 未引入传统 IM 协议兼容目标 |
| 人看视觉、AI 读文本语义 | 核心采用同版本的两种投影，展示与请求分别验收 |
| 双向表达 | 用户发送与 AI 自主发送均有流程和验收项 |
| Q11 最终修正 | 数据与工具接口均无单次语义覆盖；消息快照由核心构建 |
| 用户编辑且历史不变 | 不可变版本、个人副本与历史素材保留一致 |
| 系统建议、用户确认 | 建议只进入草稿；文本建议不可用时可手动完成 |
| 本地、无账号、同机三端共享 | 核心库独立于三个插件缓存目录 |
| 静态与短循环动图 | 格式、时长、封面、暂停和回放均有定义 |
| 开箱表情与开放方式 | 24 个内容方向处于规划状态，未声称已制作或已开源发布 |
| 三端能力边界 | 官方依据、工程推导与待实测状态分别标注 |

## 2. Schema 验证

使用 Python 的 jsonschema Draft 2020-12 验证器，显式提供 UTC 日历时间格式检查。未下载额外依赖。

8 个合法对象覆盖：

- 静态表情版本、完整消息、表情包清单结构。
- AI 发送方向、最小语义字段。
- 带静态封面的 GIF 与 animated WebP。
- 带来源引用的个人副本结构。

29 个非法对象覆盖：

- 消息、表情版本与语义对象中的动态覆盖字段。
- 空含义、纯空白、超长含义、过多语境条目。
- 未知协议版本、未知类型、无效 UUID、非法日期及非 UTC 时间。
- 重复标签、额外外部视觉地址、SVG。
- 超大文件、超大尺寸、无效摘要格式。
- 被声明为静态的 GIF、静态图携带动画时长/封面。
- 动图过长、GIF 封面、缺少动图封面。
- 错误消息方向、空包、包携带设置或消息。
- 缺少替代文本。

执行过程中发现：当前环境的默认 FormatChecker 未提供 date-time 实现，单靠 format 声明没有拒绝非法日期。验证时补上显式检查，同时在协议中写明实现必须启用真正的时间格式验证。修正后全部断言通过。

示例的名称与语义合计为 283 个 UTF-8 字节，低于 4 KiB 预算。其图片摘要及大小为占位值，没有真实素材；结构合法不等于它是可导入资产。

## 3. Schema 以外的合同

下列约束已明确归入实现与验收，未声称本次执行通过：

- 真实文件摘要、MIME、尺寸、帧数、累计解码像素和动画封面静态性。
- 包中版本引用唯一性、defaults 完整性和素材闭包。
- 相同版本内容冲突、个人副本来源与本地归属。
- 跨进程写入、导入事务、编辑冲突与崩溃恢复。
- 消息快照与已确认版本精确一致，发送不接受任意消息快照。
- 宿主绑定、投递幂等、显示回执和历史恢复。
- 实际模型请求不含 Amoji 图像输入，及不同模型的表达质量。

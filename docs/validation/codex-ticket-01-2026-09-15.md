# Codex 票据 01：Desktop 补验

日期：2026-09-15。范围：三样本接入小样，仍不是 v0.1 全部功能。实测已完成，票据关闭前按原验收条目复核。

## 实际运行路径

Codex Desktop `26.901.41600`，内置引擎 `0.153.4`；使用已安装的个人市场插件 `amoji 0.1.0-dev.1+codex.20260905153521`。本轮没有替换插件运行时代码。三个固定样本仍来自已记录的 imagegen 开发素材，包括两张静态图和一张双帧循环 WebP 及 PNG 封面。

首次先用内置引擎的 CLI 模式验证操作路径，再在 Desktop 自己的现有测试任务中重复。两类证据分开保存：

- [CLI 三样本矩阵](evidence/codex-requests-2026-09-15.json)：三个阶段，28 次实际模型请求。
- [真实 Desktop 回合](evidence/codex-desktop-2026-09-15.json)：两个任务、三个双向回合及一个纯文本历史回放回合，39 次实际模型请求；另有一次卸载任务后的冷恢复，5 次请求，合计 44 次。

Desktop 回合通过 App 任务 API 恢复已有测试任务发起，没有为这些回合另起 `codex exec` 或自建 app-server。用户点选到模型的路径是安装版 `amoji_pick` MCP 返回；AI 选择到图像的路径是安装版 `amoji_search → amoji_emit` 与配套面板。App 任务 API 仅用于自动化发送测试提示，插件程序与普通用户流程均不依赖它。

CUA 仍拒绝控制 Codex App 本体。视觉在真实任务对应的配套面板中用 CUA in-app browser 操作、读取可见 DOM 并截图；这符合票据允许原生界面或配套面板的条件。本次不宣称已目视验证原生聊天中的图片渲染，也没有重启 Desktop 应用。

## 三样本与会话隔离

任务 A：`01a0a578-be91-7dd0-ac69-e04026617843`；任务 B：`01a0a579-095d-7242-90c0-e6fe8ff96cf6`。这些是没有图片附件的专用测试任务，开发阶段截图未进入它们的输入。

| Desktop 回合 | AI 发出的图像 | 用户点选的图像 | 实际文字回应 |
|---|---|---|---|
| A 首次 | 挠头苦笑 | 一起庆祝 | 真开心，我们一起庆祝这次进展！ |
| B 首次，与 A 同时等待 | 一起庆祝 | 一步一步来（动图） | 谢谢你的鼓励，我们一步一步来。 |
| A 续聊，重开面板 | 一步一步来（动图） | 挠头苦笑 | 小失误而已，笑一笑，我们继续。 |
| A 纯文本回放 | 未发送 | 未发送 | 我理解你是在为自己的小失误温和地自嘲，带着一点无奈。 |

三个双向回合的 Amoji 调用均为 `search → emit → pick`，三者各一次。顺序调整仅用于让验收工具及时取得 `amoji_emit` 返回的面板地址，不改变两个方向各自的语义和投递路径。默认 pick-first 探针仍保留，其用户先选、AI 后回复流程已在 09-05 实际通过。

在 B 预选鼓励动图后切回 A，A 仍无选中项；在 A 选择并发送庆祝后切回 B，B 仍保留自己的鼓励选择。两个面板展示不同目标任务标识，只包含各自消息。六条消息的精确版本、方向与完整消息 ID 已写入 Desktop 证据文件；持久回执均为 `presentation=rendered`。图像加载回执不等于用户已阅读；小样的 `delivery=pending` 仍如实保留，完整投递状态机属于后续票据。

## 历史与动图

关闭 A 的面板并重新创建浏览器页后，旧苦笑、旧庆祝及新鼓励均重新加载。展开旧苦笑历史可见原 `asset_id`、`revision_id`、完整 meaning、tone、use_when 和 avoid_when。可见 DOM 的六个图片元素全部 `complete=true` 且自然尺寸大于零。最后发送苦笑后，A 有四条本任务历史，B 仍仅两条。

切换“暂停动图”后，按钮变为“播放动图”，鼓励图切换到同一固定版本的静态封面，文字语义没有变化。静态图自然尺寸为 1254×1254，鼓励图和封面为 887×887；媒体本身的帧数、时长和循环属性仍由已有真实解码检查覆盖。

本轮 CLI 矩阵还实际退出并重建了 MCP/面板进程，恢复同一任务、同一数据目录后重新加载旧图和完整定义。它与 Desktop 的面板重开、续聊请求是互补证据；不把 CLI 进程重启写成 Desktop 应用重启。跨库编辑、归档和正式卸载后的历史属于后续功能，未在本票宣称完成。

随后归档专用任务 A，App 读取结果明确为 `notLoaded`；解除归档后由 Desktop 冷恢复同一任务，实际回合 `01a0a593-89dd-7a31-90fe-d2bfb25fa135` 再次 `search → emit`。新 MCP/面板实例重新加载原四条 Desktop 消息，消息 ID、固定版本与图片均保持；展开旧苦笑完整定义并检查八个图片元素全部成功加载。恢复后的文字回应正确解释原苦笑含义。这次冷恢复另记录 5 次无图像实际请求，填补宿主任务卸载后重开历史的证据；仍不宣称重启了整个 Desktop 应用。这里“归档任务”是 QA 用于触发任务卸载的宿主操作，不是尚未实现的 Amoji 表情归档功能。

## 实际请求观测与配置还原

对尚未加载的测试任务，在用户配置中临时追加非默认的 `model_providers.amoji_observation` 定义，使其指向本机回环转发器；不改变默认 provider。发送测试提示时省略 model/thinking 覆盖，Desktop 冷恢复读取持久的 provider ID 和临时定义。精确版本的 `thread/resume` 配置加载行为已核对；最终是否成功只以 relay 实收 `/responses` 为准。

44 次 Desktop 请求全部成功解析，`inputImageParts=0`、`imageDataUrls=0`。统计检查实际 `body.input`，不是根据 MCP 文本返回类型推测。首次、工具回传、后续回合及冷恢复历史回放都在观测范围内。请求数包含等待人工点选时的模型续轮，不代表每张表情的最低必要调用数，也不表示零成本。

转发器不保存认证头、原始请求或完整提示。仓库仅保存白名单结构、固定语义、消息标识和测试结果，不包含选择凭据或实际面板能力 URL。App 读取接口对当前版本的进行中条目返回不完整，本次从这两个已知测试任务的持久 rollout 读取完成事件及工具返回；没有读取其他任务。工具和回复成功以真实记录为准。

首组四个回合与后续冷恢复各自结束后均已删除临时 provider 表，两次配置文件 SHA-256 均与各自修改前完全一致，两个转发器已退出。两个测试任务已归档，避免后续误用仅为验收准备的临时 provider；素材与语义历史仍保存在独立用户数据目录。

## 检查、修复与失败记录

- `npm run typecheck`、`npm run build`、完整 `npm test`：15/15 通过，无跳过。
- 新增 emit-first 探针的两轴审查发现顺序检查只验证子序列，可能把提前 pick 误判为通过。现已严格比较完整三工具序列，并共享成功判定；3/3 聚焦负例测试通过，三份实际 CLI 事件回放均通过。Standards 与 Spec 分别复核关闭。
- 本轮先前两次 pick-first 运行因 Edge 操作工具无法读取新面板内容而等待超时，均为失败，不混入成功请求计数。换用实际工具返回地址打开 IAB 后完成矩阵。
- 曾出现一次磁盘临时写入空间不足；随后保存成功，当前空间已恢复。没有以此改记或跳过功能验证。
- 源码、Schema、参数拒绝、幂等、会话隔离及重启合同测试继续有效；本票没有扩展成共享可编辑库，也没有实现 Claude Code 或 dsh 适配。

## 复验操作

普通用户在已安装插件的 Codex 任务中要求发送表情或使用 `/amoji`，面板显示对应任务；选择后由 MCP 返回固定语义。AI 通过检索与发送工具返回视觉，面板读取对应版本。无需手工复制语义，也无需向模型上传图片。

开发侧可用 `AMOJI_PROBE_PICK=1 AMOJI_PROBE_EMIT_FIRST=1 AMOJI_USE_PLUGIN=1 node scripts/probes/live-tools.mjs` 在实际 emit 后取得临时面板地址。两会话使用同一个明确的 `AMOJI_DATA_DIR`；恢复原任务时增加 `AMOJI_RESUME_THREAD`。默认日常工具及 pick-first 模式不变。Desktop 请求复验按上面的冷恢复路径，只临时补目标 provider，完成后精确撤回；原始日志和能力 URL 不应提交。

# Amoji 2.1.0

Amoji 2.1.0 让**表情效果**真正成为表情的一部分：带效果的表情，发送时一定附上它的效果，只作用于 AI 接下来的这一次回答。协议仍为 Amoji 0.1，RFC 更新为第 4 稿。

## 本次变化

- **发送即生效**：点选带效果的表情会直接发送并附上效果，不再有“发送 / 带效果发送”两个按钮。不想要这个效果，就换一张表情或直接打字。
- **看得见**：dsh 选择器给带效果的表情加角标；dsh 与 Claude 的表情详情都写明“发送时附带效果”和效果内容；Claude 输入框上方的发送状态会显示附带了哪个效果；市场详情列出每条效果绑定的表情。
- **去掉会话持续效果**：dsh 与 Claude 都移除了「表情效果」管理页和“对话中持续”开关。效果只跟随一条表情，不会延续到之后的消息。旧版本保存的会话规则不再附加。
- **像文字一样插话或排队**：AI 正在工作时发送带效果的表情，效果随表情一起插话（steer）或排队，转为新消息时随之进入新回合；「先等一下」「停下」这类叫停表情不带效果。dsh 宿主会为缺少效果的发送自动补上绑定的效果。
- **更严格的创作规则**：每个效果必须绑定到表情或码位；每个表情或码位只绑定一个效果；精确版本的绑定优先于码位；叫停类码位不能绑定。本地表情包编辑器、预览确认和市场投稿使用这一规则；导入更早的包时，未绑定的效果被忽略。
- **官方包**：经典与办公升至版本 `2`。「先结论后依据」（原“当前会话先结论后依据”）绑定到「进度如何」，「完成时说明依据和未知」（原“当前会话完成时说明依据和未知”）绑定到「继续吧」；其余效果绑定不变。
- AI 发送的表情不带效果；用户的明确文字仍优先于效果。

## 安装

需要 **Node.js 24+**。dsh 基线为 **0.1.5-rc.2**；Claude Mods 面向支持 Mods 的 **Claude Desktop → Code → 本地会话**，Claude Code 基线为 **2.1.295+**。

```sh
npx @deepseek-ai/dsh@0.1.5-rc.2 plugin --profile amoji add ./amoji-dsh-2.1.0.tgz --ignore-scripts
```

Claude 用户解压 `amoji-claude-mods-2.1.0.zip`，按 [Claude Mods 指南](https://github.com/5101good/amoji/blob/v2.1.0/plugins/amoji-claude-mods/README.md)安装。完整步骤见 [dsh 安装指南](https://github.com/5101good/amoji/blob/v2.1.0/docs/dsh-installation.md)。

## 兼容与数据

产品 `2.1.0`、协议 `0.1`（RFC 第 4 稿）、注册表 `0.1-r3`、共享 API `3`、数据库 `1`。数据目录与 2.0.0 相同，无需迁移；2.0.0 的升级、备份与回退说明仍然适用，见 [2.0.0 发布说明](v2.0.0.md)。

共享服务保留会话规则接口，供仍在运行的 2.0.0 客户端使用；2.1.0 的 dsh 与 Claude 不再读取或附加这些规则。共用同一数据目录的 dsh 与 Claude Mods 建议一起升级到 2.1.0。已安装的经典、办公版本 `1` 保留在库中；新的版本 `2` 随插件内置。

## 验证与限制

自动测试覆盖协议创作规则、官方包构建、共享服务、dsh 宿主与界面（含 AI 工作时插话附带效果）、Claude Mods 界面与提交钩子。效果仍只是给 AI 的提示，不授予权限，也不保证模型照做。

## English

Amoji 2.1.0 makes **expression effects** part of the expression: sending an expression that carries an effect always brings the effect along, for the AI's next answer only. The protocol stays Amoji 0.1; the RFC moves to draft 4.

### Changes

- **Send means apply**: tapping an expression with an effect sends it with the effect. The separate “Send” and “Send with effect” buttons are gone; pick another expression or type if you don't want the effect.
- **Visible**: the dsh picker marks expressions that carry an effect; details in dsh and Claude name the effect; Claude's status above the prompt names the effect that went along; marketplace details list which expressions each effect is bound to.
- **No conversation-wide effects**: the Effects page and “for this conversation” switches are removed from dsh and Claude. Rules saved by earlier versions are no longer attached.
- **Steer or queue like text**: while the AI works, an expression's effect steers or queues with it and follows it into a new turn when promoted; stopping expressions such as “Hold on” carry none. The dsh host fills in the bound effect when a send omits it.
- **Stricter authoring**: every effect must be bound; each expression or act carries one effect; an exact-revision binding wins over its act; stopping acts cannot be bound. The local pack editor, preview and marketplace submissions enforce this; importing older packs ignores unbound effects.
- **Official packs**: Classic and Office move to version `2`. “Answer first, then reasons” is bound to “Any updates?” and “Report evidence and unknowns when done” to “Carry on”.
- Expressions the AI sends carry no effect; explicit user text still prevails.

### Installation and compatibility

Requirements are unchanged from 2.0.0. Verify `amoji-dsh-2.1.0.tgz` or `amoji-claude-mods-2.1.0.zip` against this Release's `SHA256SUMS`, then install as in the [dsh guide](https://github.com/5101good/amoji/blob/v2.1.0/docs/dsh-installation.en.md) or [Claude Mods guide](https://github.com/5101good/amoji/blob/v2.1.0/plugins/amoji-claude-mods/README.en.md).

Product `2.1.0`, protocol `0.1` (RFC draft 4), registry `0.1-r3`, shared API `3` and database `1`. The data directory is the same as 2.0.0 and needs no migration. The shared service keeps its conversation-rule interface for 2.0.0 clients, but 2.1.0 adapters never read or attach those rules; upgrade dsh and Claude Mods together when they share a directory.

### Validation and limitations

Automated tests cover the authoring rules, official pack builds, the shared service, the dsh host and UI (including effects that steer while the AI works) and the Claude Mods UI and submit hook. Effects remain suggestions: they grant no permissions and cannot guarantee model compliance.

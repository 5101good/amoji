# dsh 30 组真实语义与成本对照

日期：2026-09-20。macOS arm64 / Node 24.19 / dsh 0.1.5-rc.2；安装包源码 1bf2dac27aa3cdfa701aee41b6b1dbd8644085bb。这是实际宿主模型验收，不是浏览器视觉验收，也不是所有模型的效果保证。

## 方法

预先准备30个独立场景：喜悦、感谢、安慰、疑惑、调侃、日常各4个，另有6个应克制场景。每个场景分别新建普通文字臂和允许Amoji臂，共60个真实Session，官方接口创建并先命名，避免辅助标题请求。固定同一QA工作区、标准模式、llm-ai-web网关 deepseek-v4-flash、Chat协议、Off、输出上限256、零自动重试；不改用户默认模型和凭据。

两臂都要求简短回应且不执行任务；A只用普通文字，B可以选合适表情或纯文字，不提供期望ID和标准答案。仅24项基础库可发送，旧开发样本和QA个人作品归档，固定偏好neutral/restrained/paused=false。正式前4个pilot请求单列，不计入本表。按完整固定含义和语境人工评审，允许多个合理候选，不以是否调用工具判断成功。

## 已观察问题与修正边界

- thanks-1：用户感谢AI耐心帮助，AI文字“不用谢”合理，但选择“谢谢啦”（固定含义“谢谢你给我的帮助，我真心领情”），感谢主体反向。最终修补增加一般性的发送者视角与主体/对象核对，不改该资产含义，不针对测试写答案。原失败保留，修补后定点复验单列。
- none-1：初段无依据声称此前执行过文件工具，且超出简短要求；search后第二个模型请求等待90005ms超时，宿主TIMEOUT。没有emit。未自动重试、未调高超时或换贵模型；无法据此判断最终克制。
- none-2：A正确只给git status命令，B实际调用bash执行了它，违反评测“不执行任务”限制。没有Amoji发送；这是模型指令遵循问题，不能用插件成功掩盖，也不为此修改dsh通用工具。
- none-5：A答默认limit=10，B答5，真实默认为3且范围1–5。模型可见说明缺默认值，已纳入最终工具文档修补，实际接口不变。
- think-1、think-3普通文字臂分别无依据假定重复计算属性、CSS环境；不把基线天然视为正确答案。部分两臂输出Unicode emoji，它是文字字符，不是Amoji图片，不计为插件发送。

这批结果证明已观察请求可以只靠文字运行，不证明所有模型都能理解得同样好。与纯文字相比，Amoji工具往返增加了请求和Token；未测视觉模型基线，第三方实际计费未知，不能宣称净节省费用或降低所有场景延迟。
